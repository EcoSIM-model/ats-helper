# ATS-EcoSIM pairs tooling

Takes a folder of ATS-EcoSIM inputs (one column each) or EcoSIM namelists (a row of columns, for example a
hillslope), writes a matched standalone EcoSIM case and an ATS input for each, runs both models and compares
them. The folder holds only inputs and their data; the scripts are here.

    cases/<case>/
        <test>.xml        an ATS-EcoSIM input of one column; file names in it are relative to this folder
        <test>.namelist   or an EcoSIM namelist of a multi-column landscape (see below)
        data/...          the forcing and other data the inputs refer to
        pairs/            generated by `pair` (and the runs and report); not committed

    python tools/ats_pairs.py pair      CASE [--only T ...] [--start-temperature K|xml] [--population X=V ...] [...]
    python tools/ats_pairs.py run       CASE [standalone|ats|both] [--jobs N] [--only T ...] [--container NAME]
    python tools/ats_pairs.py summarize CASE [standalone|ats|both] [--only T ...] [--container NAME]
    python tools/ats_pairs.py report    CASE [--only T ...] [--check]
    python tools/ats_pairs.py all       CASE [--container NAME] [--jobs N] [pair options]

Every `*.xml` and `*.namelist` of the folder is a test, named after the file. `all` is `pair`, `run both` and `report` in turn. `pair` warns if the EcoSIM tree's PFT parameter file differs from the one locked in the folder's `case.json`.

| command | what it does | needs |
|---|---|---|
| `pair` | for each input, `pairs/<test>/`: the standalone grid, climate, phenology and namelist, the graded column mesh, the revised ATS input `ats_match.xml` and `pair.json`; plus `pairs/README.md` with what is and is not matched | numpy, h5py, netCDF4, the ATS meshing tools |
| `run` | runs the standalone and ATS cases of the pairs with a watchdog, notes failures, starts the next test | standard library |
| `summarize` | re-evaluates finished runs from their logs, runs nothing | standard library |
| `report` | `pairs/report/index.html` (figures embedded) and `report.json` for the vegetated tests; `<test>.html` / `.json` for a test without prescribed phenology and for a landscape (one section per column) | numpy, h5py, netCDF4, matplotlib |

With `--container NAME` any command runs inside that Docker container (the workspace is `/ats-helper` there;
the case folder must be inside the workspace). The container has `ats`, the standalone EcoSIM executable, the
Python packages and, once the build is done, the `exodus` wrapper the ATS meshing tools of `pair` need
(under `$AMANZI_TPLS_DIR/SEACAS/lib`), so the whole workflow needs only Docker. Without `--container`, on the
host, `pair` and `report` need `pip install -r tools/requirements.txt` and an `exodus` wrapper on `PYTHONPATH`;
`run` and `summarize` need only the standard library but must be where the executables are.

## Microbe pairs

A case folder whose inputs have `microbe model` = true (`cases/microbe_bgc_box`, `cases/microbe_bgc_column`) is
handled by `tools/ats_ecosim_pairs/microbe.py` instead of the vegetation pairs; the commands are the same:

    python tools/ats_pairs.py all cases/microbe_bgc_box    --container NAME     # 30-day two-cell incubation
    python tools/ats_pairs.py all cases/microbe_bgc_column --container NAME     # one year, 17 transported species

`pair` keeps the input's mesh and forcing (constants, or a daily table that ATS interpolates linearly, rebuilt as the
hourly climate the standalone reads) and writes the standalone case with the same layers, soil, organic matter
(`20 exp(-0.3 L)` as the coupled start-up), litter and calendar. `report` writes `pairs/report/<test>.html`: the
environment, microbial biomass and its depth structure, the ATS functional groups, the dissolved solutes and gases of
both models, and a section on **production and transport**: for ATS the change of each species' inventory against the
cumulative EcoSIM source (the difference is what the water flux carried across the boundaries), against the
standalone's own gas exchange. The pair README lists what is not matched.

Limits of the fork's standalone EcoSIM that shape these pairs (all verified, see `pairs/README.md` of a pair):

- It has 20 layer slots (`JZ = 20`), so an input with more than 19 layers is regraded in **both** models (default
  19 layers, top layer 0.1 m: a 0.05 m top layer gave a 1.9 m bottom layer on which the ATS column lost its timestep).
- It has no prescribed-phenology input, so a pair is plant-free in both models (the ATS variant sets
  `prescribe phenology` false). `sp_phenol_in` exists only in the pinned `standalone_match` EcoSIM
  (`microbe.MICROBE_OPTIONS["sp_phenol_input"]`).
- It ignores the grid's `CNH4`, `CNO3` and `CPO4` with the microbial model on: its mineral nitrogen and phosphorus start
  at zero, and its microbial biomass starts from the soil organic carbon (hundreds of times the ATS seed).
- A run that starts mid-year counts `stop_n` from 1 January (the namelist writes start day + run length), and a history
  file that spans a year change is never closed (one file per day is written).
- `XRADH` (longwave) is read in MJ m-2 h-1 without conversion (`xradh_factor`); the box gets no `XRADH` and air
  saturated at the air temperature, because the ATS box has no surface energy exchange and any longwave given to the
  standalone heated its soil by 17-20 K through microbial heat.
- ATS visualizes the biomass only when the EcoSIM PK has `visualize ecosim state`; the pair adds it.

**Builds.** `pair` adapts to the build the executables come from, read from the EcoSIM and ATS source trees
(`--ecosim-src`, `--ats-src`: they must be the trees the executables were built from) or forced with
`--build fork|merged`; the choice is printed and recorded in `pair.json`. For the **merged** build (EcoSIM with the
restructured microbial model and the semi-implicit surface heat exchange of ATS) the generated ATS variant, never your
input, gets: the surface energy `source key` `surface-ecosim_source_linearized` with `semi-implicit surface heat exchange`
true (or false where the input has no surface energy source); 8 heterotrophic guilds; at least 5 soil layers (EcoSIM's
snow code indexes `AREA_3D(3, L, ...)` with the snow layer past a column of fewer soil layers, so the 2-cell box becomes
5 cells of 0.2 m); and EcoSIM's calendar starting on day 0 (`--start-day`: the merged standalone stops on its energy check
when it starts mid-year, and the input forcing starts on 1 January; the site and calendar parameters of the PK may be given
as values or as sublists read from an hourly forcing file, and both forms are read). The standalone gets `Acetate_vr` for
`acetate_vr` and longwave in W m-2. The merged standalone has `sp_phenol_in`, but its driver turns the microbial model off
whenever prescribed phenology is on (`EcoSIMAPI.F90`), so a microbe pair stays plant-free in both models.

The inputs name `ecosim_pftpar_20261014.nc`; where it is not in the EcoSIM tree `ecosim_pftpar_20261021.nc` is used
(`--pft-file` chooses another) and copied into the pair. The pairs were made and checked on both a build of the
unmerged `agraus/ecosim_transport` and `agraus/microbe_model` (`--build fork`) and on one of the merged `*_pinned` branches.
The pairs folder holds one build's results at a time: it is rewritten (including the standalone output) by `pair`.

## What `pair` reads and changes

Read from each input: the generated single-column mesh (depth), the run length, the van Genuchten soil, porosity,
permeability, the field capacity and wilting point of the EcoSIM PK, the initial and bottom temperature, the
hourly forcing file (the `starting year` file of the PK, which also gives the site) and, with `prescribe
phenology`, the constant `surface-vegetation_type`, `surface-LAI` and `surface-SAI`. The PFT code and canopy
height come from the vegetation type's row of the PFT file named by `engine input file` (looked up by file
name under `--ecosim-src`/`input_data`). The living population is not in the input: trees and grass use the
ERT_SatePhenol values (0.1 and 300 plants m-2), any other PFT is assumed 1.0 and marked so;
`--population TEST|PFT|GROUP=VALUE` overrides it.

Changed in the revised ATS input: the mesh becomes the graded column (default 19 layers, top layer 0.05 m,
`--layers`, `--top-dz`), data file names are rebased to the run directory, EcoSIM partitions precipitation, the
daily visualization the report reads is set, and the **start temperature is replaced** (default 274.15 K, both
models) with the bottom temperature set to that plus 0.28 K, EcoSIM's deep source temperature. The standalone
has no initial ice, so a start below freezing is supercooled liquid and the pairs disagree for months;
`--start-temperature xml` keeps the input's own value (with a warning below 0 C). Without prescribed
phenology the pair is plant-free. `pairs/README.md` lists everything that remains unmatched.

An input that cannot be matched stops `pair` before anything is written, with the reason: not a single
column (`number of cells` other than 1 x 1 x N), several PFTs in one column, no hourly forcing file, no
constant canopy evaluators, a run longer than the standalone's two labelled years (729 days), or a missing
soil parameter. Not checked: that the XML is otherwise a working ATS-EcoSIM input.

Reports compare tests of one folder together and read a 729-day, two-year run; the tests of one folder
must have the same run length.

## Landscapes: an EcoSIM namelist as the input

A `<test>.namelist` of the case folder is the EcoSIM namelist of a row of columns (a grid file with one
topographic unit per column, a prescribed-phenology file, a climate file); the ATS-EcoSIM input is generated
from it, so the standalone run is the reference and ATS is made to match. `cases/ert_hillslope` is the example
(six 40 m columns on slopes of 47, 47, 47, 47, 16 and 12 degrees, trees upslope and grass downslope). The
`pair` command reads from the namelist and the files it names (relative to the folder, else by name in the
EcoSIM `input_data`):

* geometry: the width of each column (`DHI`, `DVI`), the slope (`SL0`) and the aspect (`ASPX`, 90 or 270: down
  the row). The surface elevation is integrated from the slopes as EcoSIM does; the ATS mesh is the strip of
  columns with that surface and one element block per soil layer;
* soil: the layers (`CDPTH`), porosity from the bulk density (`BKDSI`, the particle density of the options),
  field capacity and wilting point (`FC`, `WP`, which must be written out in the grid file, not `-1`), the
  conductivity (`SCNV`) and the water at field capacity (`THW = 1`). The van Genuchten curve of each ATS
  layer is fitted through the field capacity and the wilting point;
* plants: the PFT code, monthly LAI, SAI and height of each column. ATS gets the vegetation type (the row of the
  PFT file) per column and the daily LAI and SAI EcoSIM interpolates from the months; the height is that of the
  PFT file in both models. ATS has no population input (the coupled path uses a default per root biome, 0.6
  plants m-2 for these trees and 40 for the grass), so the standalone copy gets the same population in place of
  the file's (`--population CODE=VALUE` changes the standalone side only). The ATS input visualizes the
  canopy water potential and temperature;
* water table and boundaries: a stationary horizontal water table (`DTBLIG` below the lowest column) becomes a
  hydrostatic pressure on the faces of the columns that reach it; surface runoff out of the east end (`RCHQEG`)
  becomes a zero-gradient outlet;
* the climate file gives ATS its hourly forcing (`forcing.h5`) and the site (latitude, solar noon).

Changed from the namelist for the standalone run: the start temperature (the options' 274.15 K; the grid's mean
annual temperature is set to it, as EcoSIM's deep temperature follows it), no initial snow or ice, no organic
matter or litter (as the coupling), the soil albedo of the options, the canopy height of the PFT file, the years
(`--days`, at most 365 per forcing year; the first two years of the climate file by default, labelled as
non-leap years) and the history output. What stays different is listed in `pairs/README.md`. Inputs that cannot be
matched stop `pair` with the reason: more than one row, a topographic unit of several cells, an aspect that is not
along the row, soil that differs between columns, field capacity or wilting point not written out, a water table
that is not stationary and horizontal, a plant-model namelist (`ldo_sp_mode = .false.`).

The report of a landscape compares every column with the definitions and thresholds of the column report
(transpiration, canopy evaporation, snow, surface and soil temperatures); `pair.json` records the geometry and the
cell numbering of the ATS output.

## What `run` checks

A run is **stopped and noted** when its timestep falls below `--min-dt-days` (ATS only), or at the wall-clock
or log-size limit. It **passes** only if it reached its end time (ATS: the last step line; standalone: an
hourly history sample for every hour), exited normally and has no EcoSIM `ENDRUN`. EcoSIM exits with code 0
when it aborts, so the exit code alone is not trusted. A failed run is reported with the last error text of its
log (for example a missing file or parameter). Each run directory gets `status.txt`; the case gets
`pairs/standalone_summary.txt` and `pairs/ats_summary.txt`, written when the whole case is processed.
A launch error of one test is reported as that test's failure and the others still run.

## Adding a case

1. Make `cases/<name>/` with the input(s) `<test>.xml` and a `data/` folder with the forcing file.
2. `python3 tools/ats_pairs.py pair cases/<name> --dry-run` shows the plan, or the reason an input is refused.
3. `python3 tools/ats_pairs.py all cases/<name> --container NAME`, then open `cases/<name>/pairs/report/`.

`cases/pft_tests` is the example: 14 inputs (bare ground and PFT columns over LAI) sharing one forcing file;
`cases/ert_hillslope` is the example of a namelist.

Tests: `python -m unittest tests.test_ats_ecosim_pairs` (the XML edits, case folders, parameter reading, pair
generation from a copy of `cases/pft_tests`, run classification with fake executables; no model is run).
