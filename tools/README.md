# ATS-EcoSIM pairs tooling

Takes a folder of ATS-EcoSIM inputs, writes a matched standalone EcoSIM case and a revised ATS input for
each, runs both models and compares them. The folder holds only inputs and their data; the scripts are here.

    cases/<case>/
        <test>.xml        an ATS-EcoSIM input; file names in it are relative to this folder
        data/...          the forcing and other data the inputs refer to
        pairs/            generated by `pair` (and the runs and report); not committed

    python tools/ats_pairs.py pair      CASE [--only T ...] [--start-temperature K|xml] [--population X=V ...] [...]
    python tools/ats_pairs.py run       CASE [standalone|ats|both] [--jobs N] [--only T ...] [--container NAME]
    python tools/ats_pairs.py summarize CASE [standalone|ats|both] [--only T ...] [--container NAME]
    python tools/ats_pairs.py report    CASE [--only T ...] [--check]
    python tools/ats_pairs.py all       CASE [--container NAME] [--jobs N] [pair options]

Every `*.xml` of the folder is a test, named after the file. `all` is `pair`, `run both` and `report` in turn.

| command | what it does | needs |
|---|---|---|
| `pair` | for each input, `pairs/<test>/`: the standalone grid, climate, phenology and namelist, the graded column mesh, the revised ATS input `ats_match.xml` and `pair.json`; plus `pairs/README.md` with what is and is not matched | numpy, h5py, netCDF4, the ATS meshing tools |
| `run` | runs the standalone and ATS cases of the pairs with a watchdog, notes failures, starts the next test | standard library |
| `summarize` | re-evaluates finished runs from their logs, runs nothing | standard library |
| `report` | `pairs/report/index.html` (figures embedded) and `report.json` for the vegetated tests; `<test>.html` / `.json` for a test without prescribed phenology | numpy, h5py, netCDF4, matplotlib |

`run` and `summarize` use only the standard library, so with `--container NAME` they run inside that Docker
container (the workspace is `/ats-helper` there; the case folder must be inside the workspace) where `ats` and
the standalone EcoSIM executable are, while `pair` and `report` run on the host
(`pip install -r tools/requirements.txt`). The ATS meshing tools of `pair` need the `exodus` Python wrapper:
they find it through `PYTHONPATH`, or under `$AMANZI_TPLS_DIR/SEACAS/lib` in the build container.

## What `pair` reads and changes

Read from each input: the generated single-column mesh (depth), the run length, the van Genuchten soil, porosity,
permeability, the field capacity and wilting point of the EcoSIM PK, the initial and bottom temperature, the
hourly forcing file (the `starting year` file of the PK, which also gives the site) and, with `prescribe
phenology`, the constant `surface-vegetation_type`, `surface-LAI` and `surface-SAI`. The PFT code and canopy
height come from the vegetation type's row of the PFT file named by `engine input file` (looked up by file
name under `--ecosim-src`/`input_data`). The living population is not in the input: trees and grass use the
ERT_SatePhenol values (0.1 and 300 plants m-2), any other PFT is assumed 1.0 and marked so;
`--population TEST|PFT|GROUP=VALUE` overrides it.

Changed in the revised ATS input: the mesh becomes the graded column (default 19 layers, top layer 0.05 m,
`--layers`, `--top-dz`), data file names are rebased to the run directory, EcoSIM partitions precipitation, the
daily visualization the report reads is set, and the **start temperature is replaced** (default 274.15 K, both
models) with the bottom temperature set to that plus 0.28 K, EcoSIM's deep source temperature. The standalone
has no initial ice, so a start below freezing is supercooled liquid and the pairs disagree for months;
`--start-temperature xml` keeps the input's own value (with a warning below 0 C). Without prescribed
phenology the pair is plant-free. `pairs/README.md` lists everything that remains unmatched.

An input that cannot be matched stops `pair` before anything is written, with the reason: not a single
column (`number of cells` other than 1 x 1 x N), several PFTs in one column, no hourly forcing file, no
constant canopy evaluators, a run longer than the standalone's two labelled years (729 days), or a missing
soil parameter. Not checked: that the XML is otherwise a working ATS-EcoSIM input.

Reports compare tests of one folder together and read a 729-day, two-year run; the tests of one folder
must have the same run length.

## What `run` checks

A run is **stopped and noted** when its timestep falls below `--min-dt-days` (ATS only), or at the wall-clock
or log-size limit. It **passes** only if it reached its end time (ATS: the last step line; standalone: an
hourly history sample for every hour), exited normally and has no EcoSIM `ENDRUN`. EcoSIM exits with code 0
when it aborts, so the exit code alone is not trusted. A failed run is reported with the last error text of its
log (for example a missing file or parameter). Each run directory gets `status.txt`; the case gets
`pairs/standalone_summary.txt` and `pairs/ats_summary.txt`, written when the whole case is processed.
A launch error of one test is reported as that test's failure and the others still run.

## Adding a case

1. Make `cases/<name>/` with the input(s) `<test>.xml` and a `data/` folder with the forcing file.
2. `python3 tools/ats_pairs.py pair cases/<name> --dry-run` shows the plan, or the reason an input is refused.
3. `python3 tools/ats_pairs.py all cases/<name> --container NAME`, then open `cases/<name>/pairs/report/`.

`cases/pft_tests` is the example: 14 inputs (bare ground and PFT columns over LAI) sharing one forcing file.

Tests: `python -m unittest tests.test_ats_ecosim_pairs` (the XML edits, case folders, parameter reading, pair
generation from a copy of `cases/pft_tests`, run classification with fake executables; no model is run).
