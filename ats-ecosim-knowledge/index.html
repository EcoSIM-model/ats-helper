How ATS calls EcoSIM

ATS owns the simulation clock and multiprocess coordination. Its EcoSIM process kernel exchanges column data with a linked Fortran library, then publishes EcoSIM’s water and energy feedback into ATS state.

  1. 01 / CONTROLATS coordinator

    Advances the PK tree and commits accepted timesteps.

  2. 02 / ADAPTEREcoSIM PK + EcoEngine

    Maps ATS fields into C-compatible exchange buffers.

  3. 03 / COMPUTEFortran EcoSIM

    Runs the coupled surface-balance pathway and its internal substeps.

  4. 04 / FEEDBACKATS source fields

    Receive fluxes, snow state, and carried internal state.

Runtime architecture: EcoSIM executes inside the ATS process through linked C/Fortran interfaces. Data exchange is organized by vertical soil columns.

01

Create and initialize the EcoSIM PK

ATS selects the process kernel

The XML PK tree identifies "EcoSIM for ATS". ATS’s PK factory constructs the C++ Amanzi::EcoSIM::EcoSIM class. Its constructor reads configuration and creates an EcoEngine.

CreateEcoInterface() connects the engine’s function table to ecosim_setup, ecosim_advance, and ecosim_shutdown.

Declare fields and allocate buffers

Setup() obtains the surface/subsurface meshes, declares field dependencies, registers EcoSIM-owned source terms, and defines ATS records for EcoSIM’s internal-state layout.

Initialize() allocates environment, feedback, and internal-state buffers. InitializeSingleProcess() checks that C++ and Fortran agree on container sizes before invoking setup.

02

Advance ATS, then call EcoSIM when due

The freeze–thaw example uses a weak MPC with this configured order: permafrost surface/subsurface hydrology and energy → EcoSIM. The weak coupler advances its child PKs sequentially and returns failure if a child fails. Other inputs can choose a different coupler or order.

TIMING

An hourly gate inside the PK

ATS can take smaller timesteps. The interface makes the actual EcoSIM advance call only when current_time − last_ecosim_time ≥ 3600. Previously published source terms remain available between calls.

With hydrology/energy first in this weak-coupling order, the new EcoSIM sources become available for the next hydrology/energy advance.

04

Commit, checkpoint and restart

  1. Publish feedback. CopyFromEcoSIM_process() writes the returned fields and marks EcoSIM’s primary source evaluators as changed, allowing dependent ATS evaluators to recompute.
  2. Keep EcoSIM state in ATS. CopyInternalStateFromEcoSIM_() writes the packed state into ATS records. Before a subsequent advance, those records are copied back and Fortran calls UnpackInternalState().
  3. Commit an accepted step. The coordinator calls the PK tree’s CommitStep(). EcoSIM’s implementation records the accepted time in saved_time_.
  4. Check restart compatibility. The PK declares private carried-state records for checkpointing and checks their layout version against the EcoSIM library before advancing. Output-only entries are excluded from checkpoint storage.

05

Details that affect interpretation

The coupled driver’s scope

The traced Fortran entry point calls SurfaceEBalance(). This path performs surface energy/water and snow calculations, with plant processes when enabled. ATS continues to advance the hydrology and soil-energy PKs configured in the input.

EcoSIM owns its source fields

The PK registers returned source terms as primary variables. An input that also defines constant evaluators for those same keys is rejected. This explains the two obsolete evaluator definitions removed from the copied freeze–thaw validation input.

Subsurface energy copy-back is disabled in this revision. The interface declares a subsurface energy-source field, but the C++ assignment that copies its column values back into ATS is commented out. Surface energy feedback and subsurface water feedback are actively published. Inspect the copy-back code ↗

Runtime evidence from this workspace: EcoSIM PK registration, two-rank MPI startup, and an adapted one-day coupling run passed. The adapted full 200-day case stopped with TimeStepManager: manually prescribed timestep failed after temperatures exceeded the constitutive model’s bounds. These results do not establish a passing full regression.
